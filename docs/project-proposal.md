## 1. Название и организация

- Название системы: ИС «Учёт и оценка рисков сервисных учётных записей AD»
- Организация / подразделение: Отдел информационной безопасности ООО «Софт решения»
- № из таблицы примеров (если брали): своя тема

## 2. Главная сущность и справочник

- Главный объект (одна запись процесса): задача по устранению риска сервисной учётной записи
- Справочник (вторая таблица, ссылка числом): сервисные учётные записи Active Directory
- Поле-ссылка (как назовёте в JSON/БД): `serviceAccountId`

## 3. Роли и права

| Роль | Создаёт | Назначает | Меняет статус |
|------|---------|-----------|---------------|
| Аналитик ИБ | да | нет | нет (только отменяет свою до назначения) |
| Координатор | нет | да | нет (может отменить задачу) |
| Системный администратор (исполнитель) | нет | нет | да (только у записей, где он исполнитель) |

Исполнитель не назначает себя, если этого нет отдельным требованием. Автор задачи не должен назначаться её исполнителем.

## 4. Сценарий в одно предложение

Аналитик ИБ создаёт задачу по устранению риска → Координатор назначает системного администратора-исполнителя и устанавливает срок → Системный администратор переводит задачу в `InProgress`, выполняет мероприятия и закрывает её (`Closed`).

## 6. Что не входит в семестр

1. Автоматическая интеграция с Active Directory (получение учётных записей по LDAP/WinRM).
2. Реальная отправка уведомлений по Email/Telegram.
3. Интеграция с журналами событий Windows (Event Viewer).
4. Модуль расчёта риска по сложным формулам с весами (в семестре — базовые правила).
5. Мобильное приложение.

## 7. Запас под ВКР

1. **Интеграции:** автоматический импорт учётных записей из Active Directory через LDAP и синхронизация атрибутов.
2. **Данные/процесс:** расширенный расчёт уровня риска с весами факторов, SLA по задачам, дашборды с графиками для руководителя ИБ.
3. **Масштаб:** поддержка нескольких доменов AD и лесов (multi-forest), ролевая модель с делегированием прав по OU.
4. **Уведомления и отчётность:** рассылка Email/Telegram о просроченных задачах, экспорт отчётов в PDF/XLSX для аудиторов и compliance-проверок.

## 8. Чем не копия соседа

Собственная тема вне таблицы примеров. Заказчик — отдел ИБ конкретной организации, главная сущность — задача по устранению **киберриска**, а не ремонта/брони/заявки ЖКХ. Справочник содержит специфические для ИБ атрибуты (gMSA-пригодность, привилегии, связанные системы), третья роль — «аналитик ИБ».
